# 架构与实现取舍

Capitaine Web Cursor 处理网页内容中的十种标准 CSS 特殊指针。设计重点是识别网页原有值、保留网站自定义指针，以及在动态页面和配置变化后恢复正确状态。

## 执行环境

扩展采用 Manifest V3，各部分职责如下。

| 部分 | 职责 |
| --- | --- |
| Content Script | 跟踪当前鼠标位置、选择目标元素、读取计算样式、管理扩展标记及页面状态 |
| Service Worker | 处理资源保存、生成用户级 CSS，并按具体文档注入或清理样式 |
| 弹窗与完整设置 | 编辑全局偏好、网站排除、图片绑定和热点，提供图片校准与真实指针试用 |
| `chrome.storage.local` | 持久化设置、资源和绑定 |

```text
图片与热点编辑
    ↓
本地资源及主题绑定
    ↓
Service Worker 生成 USER 样式
    ↓
Content Script 标记当前命中元素
    ↓
浏览器显示对应指针
```

Content Script 在隔离环境中执行，通过元素属性标记控制样式。DOM 和 CSS cascade（级联）与网页共享，扩展负责维护自己的标记和注入规则。

每个符合匹配条件且获准访问的 Frame（内嵌页面）独立运行。样式注入按 `documentId` 定位，使操作对应具体文档及其生命周期。

## 资源模型

内置 SVG 和用户导入的 SVG / PNG / CUR 使用同一套资源模型，保留各自的文件格式。

| 字段 | 含义 |
| --- | --- |
| `source` | `kind` 为 `builtin`（内置资源）或 `file`（导入文件） |
| `format` | `svg`、`png` 或 `cur` |
| `sourceSize` | 当前校准画布的尺寸 |
| `displaySize` | 浏览器使用的显示尺寸 |
| `hotspot` | 源画布中的热点坐标 |
| `hotspotOrigin` | `preset`（预设）、`embedded`（CUR 内嵌）或 `manual`（手动） |

Light / Dark 的覆盖绑定分别保存在 `bindings.light` 和 `bindings.dark`，以 CSS `cursor` 值为键、资源 ID 为值，未配置的类型使用该主题的内置资源。同一资源可供两个主题共用，单独编辑其中一个主题时生成独立资源，使两个主题之后可以分别调整。

内置资源以生成后的 32 px SVG 作为校准画布，热点已从原始 `.spec` 换算到这一尺寸。用户文件保留各自的源坐标系。例如，24×24 源图中的 `(12, 12)` 显示为 32×32 时，对应 `(16, 16)`。

热点换算按各轴比例向下取整，并限制在显示图像内。CUR 使用 `embedded` 模式时，由浏览器读取文件热点，人工校准后切换为 `manual`，再写入显式坐标。

### 格式处理

- 内置素材来自固定版本的 Capitaine SVG 和热点配置。生成时调整根节点显示尺寸，保留图形、滤镜和 `viewBox`，源文件通过 SHA-256 校验。
- 用户 SVG 经 XML 解析和静态、自包含校验后，以图片 URL 加载。缺少宽高时由 `viewBox` 补足，只有单边尺寸时保持原有比例。
- PNG 按原始字节和尺寸使用。
- CUR 保留完整原文件，运行时重组宽高均不超过 128 px 的图像条目，对应图片数据和热点原样保留。

单份导入文件上限为 256 KiB。

## 指针识别

通过 `getComputedStyle(element)` 获取 computed style（计算样式），再读取其中的 `cursor` 值。继承、选择器状态和运行时修改由浏览器的样式计算处理。

识别器只匹配十种目标关键字的完整值。图片声明保留给网页，即使 `url(...)` 的 fallback 是 `grab`，也保持该声明。`auto`、`none` 和其他类型原样保留。

每个 Frame 维护当前目标的活动标记。取样时先解除上一次的覆盖，再读取网页原值并重新标记，整个过程在同一个同步任务中完成。这样能区分网页原有的图片指针与扩展自身的图片 URL。

标记使用文档独立的随机名称，释放时检查当前值的归属后恢复原值。首次进入作用域和新增子树时，会清除被 `cloneNode` 复制的扩展标记。

## 动态页面与命中选择

鼠标事件、滚动、窗口变化和 DOM 变化通过 `requestAnimationFrame` 合并处理。`MutationObserver`（DOM 变化观察器）过滤自身的属性写入，将网页变化加入更新队列。

普通命中沿当前坐标逐层进入开放的 Shadow Root。存在有效的指针捕获（pointer capture）时，优先检查捕获元素，释放后恢复坐标命中。各 Frame 由自己的脚本处理事件和命中。

CSSOM（CSS 对象模型）修改、动画和 media query（媒体查询）变化可能不产生 DOM 记录，因此以定向重采样补充观察器：在文档可见且已有鼠标位置时，每 120 ms 检查当前目标。

停用时释放标记并停止取样，当前位置跟踪供重新启用时恢复使用。离开页面或失去活动状态时清除位置。

## 样式注入与更新

指针规则通过 `chrome.scripting.insertCSS()` 作为用户级样式（`USER` origin）注入，使用 `!important` 并匹配当前元素的扩展标记。内置图片通过 Web Accessible Resources 声明提供给匹配的 HTTP / HTTPS 网页。

同一套规则应用于普通 DOM、开放和嵌套 Shadow DOM，标记变化同时触发样式重算。

Auto 主题模式通过 `prefers-color-scheme` media query 选择 Light / Dark 资源。手动主题及资源配置变更由配置事件触发更新，包括换图、热点修改与恢复默认。

`chrome.scripting.removeCSS()` 需要与注入时相同的 CSS 文本，因此每个文档保留已注入规则的原文及其 SHA-256 hash（内容摘要）。hash 用于识别并复用内容相同的规则，原文用于精确删除。更新时先插入新规则再移除旧规则，操作失败时保留现存记录，供后续清理。

## 保存与草稿

全局设置与指针资源分别存储。全局设置按 `baseline` 识别已编辑字段，将保存的 `patch` 合并到最新值，并同步其他入口对未编辑字段的修改。资源绑定由后台串行合并，按引用关系清理闲置资源。

编辑器将草稿与已保存状态分开，当前资源出现外部更新时提示用户。切换类型或版本前确认是否丢弃草稿，读取或保存失败后可以在原草稿上重试。

放大预览按图像显示矩形反算源坐标。1:1 试用区与网页共用指针值生成逻辑，并标示浏览器报告的点击坐标，用于校验热点。

## CSP 与覆盖范围

用户文件以 `data:` 图片 URL 参与网页渲染。内容安全策略（CSP）可能拦截图片请求，表现为资源拒载，而非 CSS 规则失效。

收到浏览器触发的强制 `img-src` / `data:` 违规事件后，当前文档使用内置资源替代上传文件，保留内置热点覆盖。已保存绑定和文件继续保留，各文档按自身策略处理。

元素命中模型覆盖普通元素和开放式 Shadow DOM。封闭式 Shadow DOM 内部、伪元素自身的盒及原生控件子部件不在当前覆盖范围。浏览器原生拖放反馈、禁止注入的页面由浏览器处理，`cursor` 的 transition（`allow-discrete` 离散过渡）在激活期间优先于 `USER` origin 的 `!important` 声明。
